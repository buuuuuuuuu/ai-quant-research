# M12-F 回测可信度与问题股票操作

## 股票范围与预检

阻断卡片可按股票查看原检查项和有界日期证据。明确选择“从本次研究排除”时，先核对原范围、新冻结范围、研究日期、候选数和最大持仓，再生成显式股票列表和 `scope_adjustment`。它保存原股票池 ID/revision（或原明确列表）、被排除代码及当时的阻断原因。后端重新读取原 revision，并验证新列表恰好等于原列表减去被排除代码。任何变动使旧预检无效，需要重新只读检查。原股票的数据缺口不会被修改或标为修复。

## 事实摘要

新运行的 `trust_summary.json` 和 `run.json.trust_summary` 保存冻结数量、排除原因、提交时只读预检时间与结果、基准检查、实际研究交易日、预热起点、信号/指令/成交数、账户核对结果、参数哈希和代码 SHA。预检快照无法取得时显示“未记录”，不把运行成功等同数据检查通过。

按股票统计仅使用 `orders.csv` 的 `status=executed` 行：买卖笔数、`notional` 之和和 `cost` 之和。最大回撤区间从 `daily_nav.csv` 已保存策略累计净值的前高点和谷点计算，并显示端点已保存账户快照；不把端点持仓称为亏损原因。成本相对初始资金为 `total_transaction_cost / initial_capital`；相对净收益绝对值为 `total_transaction_cost / abs(final_value - initial_capital)`，分母为零显示未记录。未成交不计成交金额。因缺少稳定的平均成本、配对及公司行为口径，不计算单笔实现盈亏或股票收益贡献。静态股票范围仍有幸存者偏差。新 Excel 附加“股票成交与成本”工作表，原工作表及下载字段不变。

## 排队、取消和恢复

日线任务按不含时间变化的策略身份申请唯一 claim。同身份任务仍在排队、运行或已经完成时返回原任务。等待中的任务和取消请求争用数据库 `queued → running` / `queued → cancelled` 状态切换；只有取消胜出时才称取消成功。运行中的计算没有安全中断边界，接口明确拒绝取消。下载或回测共享锁暂时繁忙时，任务保持 queued，由有界轮询重试。服务重启后仍在数据库的 queued 日线任务不需要再次确认，使用原任务 ID、冻结参数启动；失去 worker 的 running 任务按现有租约超时规则转为失败，不自动重算。

Schema 18 在迁移事务中保留 `operation_task` 所有原列与行，并仅向状态约束增加 `cancelled`。旧运行文件和报告不批量改写；旧页面可忽略 `trust_summary`。部署前应备份数据库。迁移后的数据库不能直接用旧版应用写入；回滚应用需同时恢复迁移前数据库备份，且迁移后产生的任务不可回写到旧库。

## 人工验收

1. 用原范围预检 `000333` 并确认仍阻断；主动排除后检查新数量与候选/持仓上限，重新预检，运行详情和新报告显示排除原因。切回原范围后缺口仍阻断。
2. 提交相同参数两次，只出现一个任务 ID。队列尚未运行时确认取消并刷新历史；运行后取消收到明确冲突提示。
3. 让另一任务占用操作锁并提交回测，观察 queued；释放锁后继续。重启服务后原 queued 任务继续，不重复创建。
4. 核对 `trust_summary.json` 中的股票金额和成本与 `orders.csv` 已成交行、回撤日期与 `daily_nav.csv` 一致。旧报告链接与原工作表仍可用。
5. 分别在 390px、768px、1440px 查看阻断详情、确认框、历史任务状态、可信度卡片和局部滚动表格。
