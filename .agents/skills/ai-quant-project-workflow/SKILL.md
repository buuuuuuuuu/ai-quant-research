# 澄明项目协作方式

## 开始工作

1. 根据本次任务核对 GitHub 上相关 PR 的真实状态、head、base、最新提交、CI 和评论；不要沿用上一轮对话中的状态。检查目标分支与工作区已有改动，不覆盖他人进度。发现基线异常时说明事实，不自行换基线。
2. 阅读受影响模块的仓库约定、数据产物、API、页面和相关测试。先给出简短的原因或实施方案，然后继续完成已授权工作；不要反复询问已经明确授予的权限。
3. 区分展示、数据核验、后台同步、任务状态和策略计算。只修改本次任务需要的层；以仓库当前 Schema、字段及执行语义为准，不依赖记忆中的版本号。

## 研究与历史结果

- 保持行情复权、财务公开时间、MA、信号确认、次日执行、成交、费用、现金与持仓的既有语义。确需改变计算或历史结果时，先说明最小方案及兼容影响，按本次任务的授权边界处理。
- 将“已下载或已发布”“证据已核验”“预检可运行”分别表达。未知交易日缺口不得猜成停牌；缺失财务值不得填零；不根据最终结果倒推未保存的价格、费用或盈亏。
- 只读浏览、预检、查看计划和复制参数不得自动联网、下载、核验或运行；只有用户明确确认对应操作后才启动既有任务。旧请求、旧计划与旧冻结范围不得解锁新参数。
- 保留旧 URL、历史产物和机器字段兼容性。旧记录缺字段时展示“未记录”或准确的不适用说明，不伪造零值。

## 页面与操作

- 主要文案使用通俗中文，专业代码和价格口径可追溯。未知代码保留原文并说明暂无中文解释；动态文字正确转义。
- 点击按钮后在操作附近反馈加载、结果或错误。字段错误指出具体修复方法；必要时聚焦第一个问题。普通说明支持点击、触摸、键盘及外部点击或 Esc 关闭，重要信息不只依赖悬停。
- 保持提交、排队、执行、失败、取消与历史任务的真实状态。刷新或返回页面不重复提交，不让过期请求覆盖当前选择。
- 优先复用现有组件和任务机制。手机、平板、桌面分别检查；宽表只在局部滚动，整页不横向溢出。

## 验证和交付

1. 对行为改动使用可手算的固定数据核对产物与回归；展示改动至少运行相关前后端测试、语法和静态检查。按任务需要补全后端全量、前端全量、部署脚本、systemd 与 wheel 内容检查。
2. UI 变更在 390px、768px、1440px 实际查看操作路径并提供截图。不能用单元测试冒充视觉验收；无法运行的检查写明原因和影响，不宣称通过。
3. 交付说明改了什么、字段来源或状态语义、测试实况、未验证项、已知限制、提交 SHA、Draft PR 与 CI 状态。若用户需要服务器更新步骤，核对目标分支与实际 Schema 后给出命令及验收方法。
4. 不擅自合并 PR、连接或部署生产服务器。只有本次任务或此前会话明确授权时才执行相应外部操作；用户的最新明确要求优先于此 Skill。
