# M10-B：股票池研究看板与增量简报

## 现有路径与本阶段增量

现有路径：受管理股票 → 原同步服务 → 质量校验和分区事务 → published 行情/公告/财务视图 → StockPoolService 的不可变 revision → M10-A 个股工作台、运行范围索引和离线摘要。研究预检与补齐仍由 M9-C 独立处理。

M10-B 增加一个服务端集合查询服务 `ResearchDashboardBrief`，不会由浏览器逐股票拼接全历史 API。直接复用 published 视图、股票池 revision 解析、M10-A 的逐字 quote/页/chunk/SHA 校验和冻结研究范围查询。个股页与看板共用研究关联 SQL；新索引、旧研究任务、Copilot 计划、事件研究和有明确输入范围的条件选股按运行时输入关联。不用当前池成员反推，不扫描报告目录。

原来没有股票池简报持久身份、确认预览指纹或可靠的带时区首次采集时间。因此需要 v16→v17 迁移。HTML 继续使用 M10-A 的数据库快照存储方式，不创建外部报告文件。

## 操作示例

1. 在工作台导航打开 **研究看板**（`/research-dashboard`），页面自动加载默认池。假设已有“消费研究池”，也可以从选择器切换。
2. revision 留空表示选择当前 revision 的冻结名单；填 `2` 就严格读取 revision 2。找不到时返回 404，不回退；当前已归档池必须显式指定历史 revision。
3. 截至日期默认上海今天，为当前浏览；选过去日期为历史 `as_of`。管理状态、任务和身份仍是当前本地上下文，页面明确提示，不能当成历史重建。
4. 窗口起点留空时，优先使用同池、同 revision、同模板、同复权/阈值/基准的前一份简报之后一天；没有可比较简报则最近 7 个自然日。用户也可以明确选起点。
5. 先看覆盖与未知项，再看公告、财务、已接受事件、待审核、迟到资料、行情观察和既有研究。股票列表按代码/名称筛选、分页；API 也支持按池顺序、代码、最新公告或行情日期排序。
6. 点击 **预览简报**。预览只读，不保存简报，不创建补齐或研究任务。核对资料后点击 **生成不可变简报**，并确认。
7. 本地证据或范围变化导致指纹与预览不同，生成返回 409，请重新预览。切换参数会使旧预览失效，生成按钮禁用。
8. 点击单股链接进入 `/stocks/600519`，在个股页查看公告、原文、事件和运行结果，也可使用原研究准备表单。回测、实验、选股和摘要链接保留各自身份；组合指标不代表单股表现。
9. 历史简报列表打开的是保存时快照，HTML 导出只接受 `brief_id`。页面展示最近100份；更早记录用分页列表 API。
10. 缺数据时先去个股页做研究预检，再独立查看和确认补齐计划；完成后手动刷新看板。生成简报不会确认补齐、执行研究或联网。

## 时间窗口、迟到资料和历史限制

- 对外使用 ISO 日期，时区 `Asia/Shanghai`。
- 公开窗口统一为 `[window_start 当日00:00, as_of 次日00:00)`。交易行情仅用该日期边界之前的已发布记录。
- 公告和财务 `published_at` 是项目原有的上海本地公开时间。报告期、公开时间和采集时间分别保存，不能替换。
- 新增 `first_visible_at TIMESTAMPTZ` 是同步发布事务中的本地首次可见时间；查询/序列化统一为明确的绝对时刻（UTC ISO），不依赖服务器时区。事件原有时间字段同样是带时区时间。
- 在公开窗口之前公开、在采集窗口内首次可见的记录进入“迟到资料”。使用前一份简报时，采集窗口从该简报生成请求开始时间起算（不晚于读快照，保守重放避免并发发布遗漏），避免上一份在当天结束前生成后，随后采集的资料遗漏。
- 迁移不把历史无时区 `ingested_at/observed_at` 猜成 UTC。旧记录新增字段保留 NULL；这类旧资料显式标记 `arrival_time_unknown=true`。已早于公开窗口的旧资料也纳入有界历史资料区，可能重复展示，不能声称本次新采集。
- 新公告首次采集批次保存在 `first_source_batch_id`，后续刷新不覆盖；旧公告该字段未知，当前 `source_batch_id` 不伪装成首次批次。财务原公开版本和批次已有不可变约束。
- 历史模式不使用公开时间之后的资料；已知首次可见时间晚于 `as_of` 的公告/财务也不会提前进入简报。管理状态、任务、文档解析上下文和不能重建的审核历史分别标注限制。
- `accepted` 只有在审核时间早于边界且通过 M10-A 证据校验后才进入主要事实。`needs_review`、`insufficient` 或证据失败进入待核查区；`rejected` 不进入事实/待核查清单。
- 财务只展示有来源的值、单位、报告期、公开版本和批次，不自行算增长率；缺失不填零。

## 行情观察

复用 published 日线，每股最多取截至日期前21行：最近一行与前20行。查询返回后在数据库锁外计算。

- 相邻可用收盘价变化：`(latest_close / previous_close - 1) * 100`。默认绝对变化阈值5%，范围0–30%。这不是对中间缺失交易日或停牌的豁免。
- 成交量倍数：`latest_volume / mean(previous 20 valid volumes)`。默认2倍，范围1–20；前20条不足、缺值或均值为0返回 unknown。
- 股票与基准最近日期不一致明确提示；基准缺失保持 unknown。
- 快照保存复权方式、公式、阈值、窗口、基准、输入日期/价格/量及来源批次，可复核计算。无完整历史复权版本，尤其 qfq 的严格历史版本可信度为 unknown。
- 不生成买卖评级、目标价、收益预测、因果解释。

## 快照与并发

`research_brief` 保存 `brief_id`、唯一 fingerprint、pool/revision、日期窗口、时区、冻结 symbols 及其摘要、canonical snapshot JSON、HTML、HTML SHA-256、actor 和生成时间。模板版本、完整参数、覆盖摘要、证据身份、来源批次和研究输入摘要存于 snapshot JSON。

fingerprint 是 canonical 快照的 SHA-256，简报 ID 为 `brief-<fingerprint>`。来源条目超过展示上限时仍计算有界 SQL 输出的全集来源摘要，未显示条目的变更也会使预览指纹变化。生成时间和 actor 不参与证据指纹，相同证据重复生成返回原简报及原创建者。

预览返回 `{snapshot, fingerprint}`；生成必须提交 `confirm=true` 和 `expected_fingerprint`。服务端重新解析池并取得一致读事务快照，与预览指纹比较。变化返回409；通过后释放读锁，在锁外计算行情、组装快照与渲染。最终短写事务原子提交 snapshot+HTML+创建审计。

所有数据库连接使用现有路径级跨线程、跨进程 DuckDB access lock，并依靠数据库唯一约束兜底。并发同指纹仅一个持久记录、一个HTML和一次创建审计；没有可变后台简报 worker，所以不引入新的 claim/owner/heartbeat 状态机。

失败回滚，渲染失败不留下 HTML 文件；失败审计不包含原始请求、quote 或密钥。导出复核 JSON 和HTML摘要，attachment + CSP sandbox + nosniff。HTML 在数据库内，不存在临时文件、路径穿越、外部孤立报告或文件原子替换问题。

备份仍 operation → access，简报仅 access，渲染时不持锁。备份得到插入前或完整插入后的数据库，不会得到半份简报。

## 规模与截断

最多500只股票；股票页最多100行；每个增量区最多100条，事件来源最多50条，每事件最多50个有效quote、每quote最多2000字，完整快照最多4MB。上限或错误不会伪装成完整成功；截断区显示 `truncated`。accepted/review 的 total 为已逐条复核的展示数量，`source_total` 表示待分区来源全集数量。

行情覆盖按所选证券集合聚合，观察最多500×21行。证券规模增加不增加逐股票查询数；只有最多50个事件复核使用既有有界查询。500只池在128MB DuckDB限制下的集合查询回归覆盖查询次数和快照大小。大的实际历史库仍会扫描所选证券的历史索引/视图，应遵守约2GB部署边界，不增大并发。

研究缺口是明确的基础覆盖诊断，不等于对任意回测参数的研究就绪判断；最终由M9-C预检决定。

## API

沿用工作台认证与actor：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/research-dashboard/pools` | 只读active池选择器，最多200 |
| GET | `/api/v1/research-dashboard` | 看板、分页/搜索/排序及增量区 |
| GET | `/api/v1/research-dashboard/deltas` | 同一集合快照的增量查看入口 |
| POST | `/api/v1/research-briefs/preview` | 只读预览和fingerprint |
| POST | `/api/v1/research-briefs` | 明确确认后保存 |
| GET | `/api/v1/research-briefs` | 历史列表，支持pool和分页 |
| GET | `/api/v1/research-briefs/{brief_id}` | 已存快照 |
| GET | `/api/v1/research-briefs/{brief_id}/html` | 受保护的HTML导出 |

预览请求示例（用实际pool_id替换）：

```json
{"stock_pool_id":"pool-example","stock_pool_revision":2,"window_start":"2024-03-01","as_of":"2024-03-20","adjustment":"qfq","price_change_threshold":5,"volume_ratio_threshold":2,"benchmark_symbol":"csi000300"}
```

生成使用同一请求，另加 `confirm: true` 和返回的 `expected_fingerprint`。不要修改股票列表；服务端只使用保存的池revision。404表示身份不存在，422表示字段/边界非法，409表示归档冲突或证据变化。

## Schema v17 与升级

最小变更：新增 `research_brief` 和两个索引；announcement 增加 nullable `first_visible_at`、`first_source_batch_id`；financial_report 增加 nullable `first_visible_at`。不回填虚构首次可见时间，不创建历史简报，不改旧行的公开时间/证据/任务/股票池revision。

人工部署按原停写 → v16备份并verify → 安装新wheel → 服务用户 `ai-quant data init` → 核对当前/预期17 → 新备份并verify → 恢复服务流程。默认部署预期版本更新为17。回退前保全新增数据，按已验证v16备份恢复；不要让旧程序直接打开v17写入。

本任务仅提交Draft PR，不连接或部署生产。

## 合并风险清单

| 风险 | 控制和验收 | 保留限制 |
| --- | --- | --- |
| 历史资料提前可见 | 公开/采集双边界、上海/UTC午夜测试、财务版本隔离 | 旧采集时区未知不伪造 |
| 预览和生成不一致 | 强制确认指纹，变化409 | 数据在生成读事务之后更新，已生成快照仍代表该事务时点 |

| 前端串池或旧结果 | 请求代数隔离、参数变化清空、忙碌禁用和重复点击测试 | 历史列表页面最多100份 |
| 资源使用 | 集合查询、固定上限、4MB快照、500只/128MB回归 | 截断需转个股页查看更多 |
| 迁移与回退 | 逐版本事务、故障回滚、历史行保留、备份并发验证 | 必须人工备份后升级 |
